## Recent Versions

### v2.1.34
- Improved export processing.

### v2.1.33
- Limit the request rate to 12 requests per minute per unique export identifier for `retrieveExport` and `retrieveExportFile`, returning `429 Too Many Requests` when the limit is reached.

### v2.1.32
- `listClientTransactions` endpoint now returns only transactions where the latest revision belongs to the specified client. Previously, if any revision of a transaction belonged to the client, it was returned.

### v2.1.31
- Added `Retry-After` header to `E_EXPORT_NOT_COMPLETED`, `429 Too Many Requests` and `503 Service Unavailable` responses to indicate the number of seconds to wait before retrying.

### v2.1.30
- Limit on the number of exports in `PENDING` or `WORKING` state per TSS has been set to `10` in the `triggerExport` endpoint.

## Major Version: v2.0.0

### Overview of changes

- The set of operations, path parameters, JSON schemas of requests and responses have been changed since v1.
- The TSS is fully certified. All certified components have been integrated in the API.
- New URLs have been introduced. Use `https://kassensichv-middleware.fiskaly.com` for **ALL** calls to the API.
- There are **fiskaly sign Middleware** operations and common operations in the API.
- The resources created with v1 cannot be transitioned to v2. All TSS resources must be created again with v2.

### Changes in authentication

- `authenticateApi` hasn't been changed since v1.
- `authenticateAdmin` has been added for administrative operations.
- `logoutAdmin` has been added to exit administrator mode.

### Changes in TSS handling

- The lifecycle states of a TSS resource are `CREATED`, `UNINITIALIZED`, `INITIALIZED`, and `DISABLED`.
- `createTss` triggers the creation of a TSS instance and returns the PUK.
- `updateTss` is used to change TSS state.
- `changeAdminPin` changes the PIN for Admin Authentication.

### Changes in client handling

- The lifecycle states of a client resource are `REGISTERED` and `DEREGISTERED`.
- `createClient` puts a client in the state `REGISTERED`.
- `updateClient` updates the state of a client (deregister/re-register).

### Changes in `TEST` environment

- TSS instances in the `TEST` environment that have been disabled, or have been inactive for over 14 days, will be wiped at least every Sunday.
- You can have up to five TSS in the states `CREATED`, `UNINITIALIZED`, and `INITIALIZED`.
- When wiped, TSS states are set to `DELETED`.

### Log Messages

- Transaction Logs (as in v1)
- System logs generated by SMAERS component
- Audit logs generated by CSPL component

## Version Information

The fiskaly SIGN DE API follows **Semantic Versioning** (https://semver.org).

The version number has a pattern of `MAJOR.MINOR.PATCH`:
- `MAJOR` version: incompatible API changes
- `MINOR` version: backwards-compatible functionality additions
- `PATCH` version: backwards-compatible bug fixes

The current `MAJOR` version `2` is reflected in the API's base URL: `/api/v2`
